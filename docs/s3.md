# S3 — Object Storage

The OpenBI platform uses S3 for durable object storage. Locally, this
role is filled by MinIO; in AWS, it's filled by S3 with the same API.

## Buckets

Three buckets mirror the OpenBI data lifecycle:

| Bucket | Purpose | Versioning | Lifecycle |
| --- | --- | --- | --- |
| `openbi-raw-<suffix>` | Landing zone for source data | On | IA @30d, Glacier @90d, expire @365d |
| `openbi-processed-<suffix>` | Cleaned/derived data | Off | Expire @90d |
| `openbi-models-<suffix>` | Trained ML artifacts | On | Non-current versions expire @90d |

The `<suffix>` is a globally unique string (typically the AWS account
ID) because S3 bucket names must be unique across all AWS accounts.

## Design decisions

### Encryption

**Default: SSE-S3 (AES-256).** Free, always on, no key management.
Encryption at rest happens automatically.

**Optional: SSE-KMS.** Set `encryption_type = "aws:kms"` and provide a
`kms_key_arn`. This gives you:
- An audit trail (every access logged to CloudTrail)
- Key rotation control
- Fine-grained access policies via KMS grants

Cost: ~$1/month per key, plus $0.03 per 10,000 KMS requests. For a
small data platform, that's pennies; for a large one, KMS request costs
can add up because every read/write involves a KMS call.

**What OpenBI does:** SSE-S3 by default. SSE-KMS documented as an opt-in
for teams that need the audit trail.

### Versioning

`raw` and `models` have versioning on. `processed` does not.

- **`raw`**: source data is precious. If a pipeline overwrites a file
  by accident, we want the old version back.
- **`models`**: model history matters. Being able to retrieve the exact
  model from a specific training run is valuable.
- **`processed`**: derived data can be regenerated. Versioning adds
  cost without benefit.

### Lifecycle

**`raw`:**
- Objects move to Standard-IA after 30 days (cheaper storage, slower
  access, but raw data is rarely read after ingestion)
- Move to Glacier after 90 days (cheapest, retrieval takes hours)
- Expire entirely after 365 days
- Non-current versions (from versioning) expire after 30 days

**`processed`:**
- Objects expire after 90 days

**`models`:**
- Non-current versions expire after 90 days

These are lab-appropriate values. A production deployment would tune
them to data volume and access patterns.

### Public access blocked

Every bucket has `aws_s3_bucket_public_access_block` with all four
flags set. Even if a bucket policy accidentally allowed public access,
this blocks it. This is defense-in-depth.

### Bucket policies

Each bucket has a policy with two statements:

1. **`DenyNonAccountAccess`** — denies `s3:*` to any principal outside
   the AWS account. The bucket remains accessible only from within the
   account.
2. **`DenyInsecureTransport`** — denies any request that isn't over
   HTTPS.

### What's not in the module

- **IAM policies for pod access.** Those come as IRSA roles in the
  phases that need them.
- **S3 event notifications.** Added later when there's a consumer
  (typically SQS, from Phase A7).
- **Cross-region replication.** Documented as a production pattern but
  not implemented (would require a second region).

## Using S3 from Python

`python/s3_operations.py` demonstrates the standard boto3 operations:

```bash
export AWS_REGION=eu-central-1
export OPENBI_S3_BUCKET=openbi-raw-123456789012
python python/s3_operations.py
The script:

Describes the bucket (versioning, encryption, public access)

Lists a few objects

Optionally (with OPENBI_S3_WRITE=1) uploads a test object, reads it
back, generates a presigned URL, and cleans up

These are the same boto3 calls the OpenBI pipeline uses against MinIO
locally. The only differences are endpoint_url and credentials.

Presigned URLs
A presigned URL is a temporary, credential-free URL that grants access
to a specific object for a limited time. This is how you give a client
access to an object without giving them AWS credentials.

python
url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": "openbi-raw-123456789012", "Key": "data.csv"},
    ExpiresIn=3600,  # 1 hour
)
The URL contains a signature derived from the request and the signer's
credentials. Anyone with the URL can access the object until it expires.
